> Until I tell you to change it, use Lazy mode for all subsequent Runner runs and planning.

Until the owner changes it, explicitly request supported `lazy` mode for every new
`plan-authoring`, `plan-execution` and `polishing` run, including fresh replacements.

default or requested value alone does not establish the resolved mode. On mismatch, use
a supported stop and reconcile the fresh launch; do not silently select `independent`.

Lazy uses primary self-review and read-only Worker confirmation, not an independent Reviewer.
Require and report the actual verification supported by that mode. Do not claim independent
Runner review or add a compensatory pipeline merely to undo the owner's selected mode.

mode-selection defaults for new runs only. In particular it applies to Runner review-role

authorship, mandatory checks, Native/HOST assignments, retirement or commit boundaries.

Standing commit authorization requires the current mode's actual verification and all other
applicable gates; polishing remains stage-only and push/amend permissions do not change.

unchanged. Carry the selected mode in fresh supported launch inputs; this prose does not
mutate an existing run or authorize hand-editing its configuration.
