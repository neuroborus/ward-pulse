# State and artifact identity

Keep evidence layer-specific. For UI instrumentation, follow [ownership, result and artifact checks](../../../../docs/ANDROID_TOOLCHAIN.md#routine-verification).

## Distinguish the layers

| Layer | Relevant identity/evidence |
| --- | --- |
| Source | Owning commit/dirty content and generator/provider symbols. |
| Generated resources | Exact XML/images produced for that candidate; drift checks. |
| Built artifact | APK/resource hash, package/version code and signing identity. |
| Installed artifact | Actual installed APK/resource identity on the selected target, using the uniquely resolved package-manager APK path; never assume a basename or take the first match. Missing/split/multiple paths remain unresolved. Use the producer's supported pathname contract, retain bounded actual paths before guards and quote transport arguments rather than invent a narrower character whitelist. |
| Active rendition | Current foreground app/page or face renderer's resource package and instance. |
| Effective inputs | Delivered summary/order, provider bindings and live values/TITLE where observable. |

A shared versionName, installed package or successful build does not collapse these into one proof. For WFF, distinguish the Wear app from the separate legacy/Push face package. An installed newer Push face is not evidence that the active legacy instance uses it.
Static default-provider policy does not prove a retained instance's effective binding.
No-clean semantic isolation remains mandatory: prove actual compiled payloads, effective flags, resources and validated signatures; Source BuildConfig, certificate or versionName alone is insufficient. Cross-build signed-APK byte reproducibility is a separate requirement when the task requires it.
A whole-APK hash change triggers scoped inspection, not an automatic code-regression verdict. Retain failed diagnostics and unknown variation cause; equal ZIP payloads do not prove signing-block-only variation. Semantic equivalence must never waive a required byte-reproducibility gate.
Record necessary identities before/after the action; never infer an active renderer from the APK most recently built or installed. Preserve the exact actual built→installed→active SHA-256 identity join; payload equivalence never replaces it. When reviewing active or changing Source/artifacts, retain and hash the same acquired bytes or bracket the read with matching before/after hashes; a post-read-only hash does not prove which body was reviewed. Content movement invalidates that review-to-bytes binding: reread and rebind the actual candidate before making a claim.
Before diagnostic stripping or an owner-scoped comparison, resolve the exact owning Source's supported owner/layout catalogue, including supported legacy layouts, rather than a remembered name pattern; inventory the complete closed footprint, unique names/owners and node/subtree/descendant counts on unmodified bytes, and retain actual unmatched names plus artifact hashes before the guard. Validate the Source's actual predicate; a selector/catalogue mismatch leaves comparison scope unresolved, not a product-diff verdict. A fresh read cannot reconstruct an unretained earlier failing set; never silently exclude actual changes outside the authorized footprint.
Removing a parent also removes descendants, so removed-root counts prove neither missing diagnostics nor complete stripping. Handle diagnostic-only wrappers/carriers by closed rules restoring normal structure, then compare WHOLE normal content including renderable literal padding; never silently discard unmatched content.
Before treating a diagnostic observer as feasible or expanding its harness/matrix, verify actual caller UID/package/context, service/component and instance scope against pinned official API preconditions/access. Public API does not mean unrestricted cross-package capability.
Establish the actual OS/API producer of required evidence and its supported type/format/version; a synthetic positive parser fixture proves no producer. Bind queried field and store-key names to that producer or exact owning Source before acquisition, and retain the bounded actual result. For Dart VM reads, derive the `package:` namespace from the owning package's current `pubspec.yaml` name and qualify read-method parameter names against the installed public protocol; repository labels and object-domain names do not establish either representation. Record each field's authority/domain; canonical IDs, observed renderer IDs, provider/system IDs and returned typed/client keys retain their proven domains, without presumed numeric equality or interchangeability. For a digest derived from structured output, bind the exact producer field/leaf versus its enclosing record and actual byte serialization, including UTF-8 and any trimming/newline transformation; scalar and container digests are different domains. Resolve owner-specific envelopes and schema tags through the actual owning parser before projecting fields. Before reusing a viewport or OS-state projection across targets, qualify the required named fields within their actual producer/Source-owned record; field adjacency and same-named fields in sibling records are not interchangeable, including registered-instance versus renderer-registry metadata and global versus per-group OS state. Preserve an unqualified failed sample as Unknown without invalidating independently qualified evidence or reconstructing its unretained predicate inputs. When nested maps reuse typed keys, qualify the exact parent map and require a unique typed leaf within it; bounds and margins remain separate domains even if their keys match. Detect duplicate matches before collapsing a selected map into keyed values; hold ambiguous leaves rather than letting later matches overwrite them. For complication binding comparisons, select the unique current `data=` record within each runtime slot through the owning parser before projecting its `dataSource`; an all-record slot scan may also include other records. Do not deduplicate repeated matches to manufacture current-record uniqueness or label another record pending/cache without producer evidence. Missing fields in an unqualified representation remain Unknown, never default-empty.
For installed-package commands, bind the exact Source/artifact applicationId; a Kotlin namespace or component class package is not the installed package identity. For Android UID/focus guards, follow [Package UID and full-window focus preflight](../../../../docs/ANDROID_TOOLCHAIN.md#package-uid-and-full-window-focus-preflight): qualify the exact unique PackageManager package record and the current full WindowManager representation before projecting fields. Keep Android user ID, app ID and full UID distinct; a dump's `userId` label does not establish their equivalence. An empty projection from an unqualified subsection remains Unknown, and a later corrected read is a separate sample.
For an owner uniqueness guard over full WindowManager output, qualify relative/full Android
flattened `ComponentName` forms before comparing package plus fully qualified class; expand a
leading-dot class only against that component's declared package. Retain bounded raw forms,
parse validity and the expected/actual semantic join before representation or equality guards
can abort. Window focus and focused Activity records remain separate domains; this scoped
owner comparison neither establishes instance/task identity nor normalizes exact-byte/digest guards.
For line-oriented inventories, count producer-qualified records rather than split stdout lines: a blank line is not an endpoint tuple. Retain bounded privacy-safe rows; unresolved nonblank rows prevent complete count/membership claims and must not be discarded as empty. Record-level interpretation does not replace or normalize raw bytes when the owning guard requires exact output-byte equality.
Apply guards to the actual operation/phase: requester calls require proved system-ID/provider/current active-target identity; independently authorized read-only acquisition/slot reads do not inherit that join unless their contract requires it. Other mutations retain their documented ID/ownership/current-target/custody guards. Distinguish not-invoked, unavailable evidence, denied/rejected, domain-unresolved, forwarded/processed and painted; never infer a later stage from an earlier one. Apply ordinary same-signer `install -r`'s own procedure and phase instead of importing controlled-summary cold-load/no-writer requirements.

For multi-phase inline probes, retain bounded privacy-safe facts before each guard: phase/guard identity and read time, relevant producer/context (including CLI project/entry context when applicable), queried-field presence/validity and required unique-owner/target resolution, expected/actual comparison inputs and the exact predicate mapping. Bare assertions or tracebacks alone are insufficient; compound syntax is acceptable when its predicates map to those retained facts. Missing fields do not prove target absence. If a guard fails, preserve its known outcome and independently established facts. Leave missing failure-point facts, unproved guard attribution and unproved causes Unknown; label later observations as fresh samples, not reconstruction.

Use a bounded actual minimal probe where needed; distinguish contract support, observed results and unknown enforcement. Keep unproved capability Pending: no default/cache substitution, identity swaps, access bypass or unbounded framework growth. Redacted inputs/missing mappings stay unproved; no guessed internal numeric IDs or resource-filename joins.

For Activity/task claims, inventory unique relevant ActivityRecord identities and task IDs from a complete current native snapshot. Cross-check relevant top/resumed records; repeated references are not additional instances. Hold instance-count claims when the dump/projection is incomplete or contradictory, including a top/resumed owner omitted by the parser, until fresh complete observation resolves it. Keep historical and fresh inventories separate; later observations do not reconstruct unsupported earlier stage counts.

For claims about which complication slot/type dispatched a tap, shared PendingIntent identity, caller UID, coordinates or a configured binding alone do not identify the hit. Join actual renderer hit-event evidence to the current
instance/slot, effective provider, current data type and successful destination; DOWN alone is not completed dispatch.
Keep canonical/runtime slot IDs distinct. For raw resources, bind each lookup to the exact APK bytes and resolve the requested route through that variant/embedded APK's own resource table BEFORE EACH ZIP read, including batched measurements; reuse only a route bound to identical bytes, never infer archive-path equality from a shared logical name such as raw/watchface. Never transfer debug/Legacy ZIP paths to release/Push.
Before constructing invocation arguments, verify how the owning Source serializes/parses each field and the exact representation it compares; full components, simple class names and IDs are distinct domains. Read metadata from the exact owning element and named field VALUE in its actual emitted representation; nearby IDs/substrings or assumed encoding are not attribute proof. Missing, unparsable or ambiguously resolved fields/records stay nullable Unknown, never an inferred false/default; classify a UI-state match as true or observed nonmatch as false only after validating the query/schema and uniquely resolving the owning record with a present valid field.
Before asserting identity, retain bounded variant and expected-versus-observed resource-route facts. Bind asset membership/counts to exact operation-approved names and record the full archive inventory separately; broad prefix/glob count alone does not establish selected-catalog membership/cardinality. For APK ABI guards, resolve each owning library's build configuration and retain its actual archive paths before counts; a Flutter engine target does not prove absence of independently packaged custom JNI ABIs. Missing lookup stays Pending; no guessed alternative paths or raw sensitive dumps.
Join canonical IDs with actual native instance/slot evidence; numeric IDs alone do not prove that mapping, and local proxy hashes do not prove cross-process token identity.
If the join is unavailable, keep type-specific provenance Pending while preserving separately proved common-entry, navigation/cycle and restoration results.

## Refresh and retained state

Prove the specific surface/binding that needed updating. A request to update all producers
is not a receipt that every bound complication received current data. One provider's
number changing does not prove another split half's TITLE, value or binding refreshed.
Inspect the actual paired halves and possible stale extra-half route after reorder,
selection changes or missing-pair data. Use the owning WFF/provider rules for slot names.

Where possible, distinguish producer output, effective binding and active scene through
supported diagnostics and normal app/renderer operations. A corrected image after scene
recreation supports a stale-layer hypothesis; it does not identify that layer or prove a
durable product fix by itself. When the owner explicitly requests a product repair, manual
restoration or face cycling does not complete or cancel that request or transfer the fix to
the owner. Keep the issue open and continue available authorized Runner Source/test work
within existing ownership boundaries while device acceptance stays Pending. Do not require
the owner to repeat the repair request; restored paint alone does not establish its cause.
For an owner-requested causal diagnosis, reversible lock/unlock
symptoms or an API default do not finish the investigation. Continue available bounded
comparisons from receiver through selected data to consumer; inspect the exact installed
implementation when a boundary obscures the consumed data. Pending or Unknown does not
justify stopping while a supported next diagnostic is available. Keep unavailable causal
evidence Pending and name the concrete prerequisite that prevents further investigation.

For SDK-based installation guards, bind packaged `uses-sdk`, the actual device API level,
the owner's feature/client API support and the selected rendition independently. Do not use a
minimum-SDK proxy to establish feature availability or exclude implicit installer effects;
qualify the actual owning support/installer conditions. Retain bounded measured facts for
each predicate before it can abort; missing qualifications remain Unknown.

Before an installer/device recipe touches a protected artifact cohort, inspect expanded commands, aggregate task/module installs AND bundled assets, manifest metadata and possible platform-receiver updates; reconcile EVERY affected package with the authorized phase, not only the main APK. For protected Wear Push retention, compare the candidate embedded APK with the retained installed APK by exact bytes, validated signer and variant-owned resources BEFORE installing the host; equal versionCode or an explicit app-controller/callback guard does not establish platform preservation. Follow [Watch Face Push builds](../../../../docs/ANDROID_TOOLCHAIN.md#watch-face-push-builds).
Hold a protected retained/bundled identity mismatch unless the owning accepted migration explicitly covers that exact new cohort. Hold other unreconciled module/package or implicit-update effects; use a supported scoped owner route or return the recipe/provisioning finding to actual Runner. Do not assume a narrower task prevents platform reactions.
Record actual affected installed versions/hashes before and after; unexpected advancement remains a failed preservation gate/gap, never a UI Update witness inferred from test success. Keep cause unproved unless established independently; task membership or installer attribution alone is insufficient.
After an authorized install/update, inspect the whole affected native UI again. Updating only the Wear APK
does not establish that the separately installed face changed, that its active instance refreshed or that old slot bindings were migrated.

After each app/Settings launch, navigation transition or app/face handoff, join current full-window host focus and the uniquely identifying settled page hierarchy with the full first original showing the expected unobscured page, qualifying page labels in actual native semantic fields (merged Flutter labels may occupy `content-desc` while `text` is empty), without substituting hints/accessibility descriptions for entered form values; an internal module may share or asynchronously change its host/component, so freshly qualify the actual owning host package/component together with the unique page; a remembered Activity class is not an exclusive host allowlist or page/expiry proof. Prepare any necessary supported bounded controls and their page/host guards before transient entry. Immediately before input on a transient/time-sensitive target, including after intervening analysis/tool work, revalidate the current full-window foreground, viewport and uniquely identified visible enabled target on the intended page within the final input operation; derive input bounds from that readback and fail closed if the page/target has expired or become ambiguous. An earlier picker image or a bounded input hold, whether active or ended, is not current target proof; never tap remembered bounds.
For semantic page matching, qualify the Source-backed page marker within the actual merged field or line segments; the whole `text` or `content-desc` attribute need not equal the visible heading. Preserve unique current-page resolution and keep exact byte/digest guards unchanged.
Return/view the actual image to the model and evaluate it BEFORE the next screen-dependent decision, input (including HOME to check widgets after an app launch), mutation, capture batch or dependent success, delivery or approval evidence write, or user-facing claim that the UI has progressed or been restored, including ordinary planned prefix continuation; queuing a capture or view_image/image with those actions or evidence writes inside one functions.exec is not inspection. Record launch/capture attempts as attempts; write dependent success, delivery or approval evidence only after inspecting the actual returned frame and confirming the claimed artifact/window. An old image/node is not live input authority; if the target is gone, stale or ambiguous, stop or reopen the supported route and reinspect instead of tapping cached bounds.
Independent read-only batching and unconditional necessary failure-safe cleanup/recovery need no image gate; ordinary planned prefix progression is not this exception. Next-case pre-write preparation, including process retirement and quiet-writer checks, is dependent case progression, not failure-safe cleanup: explicitly checkpoint that the model has viewed and evaluated the prior frame, then begin that prefix only in a separate subsequent tool call. Recovery establishes neither image inspection/PASS nor permission for further case advance. For physical targets, use the
[launch/navigation guard](../../android-devices/references/commands.md#guard-launches-and-navigation).
Active wallpaper/renderer mode, UIAutomator idle or launch success alone does not prove compositor handoff.
If a prompt/notification covers the face, stop as an environment obstruction, not Source/UI PASS. Use only safe
existing dismissals; never reset or provision for capture. Inspect previous-page residue through bounded
observations of intended settled content; allow real clock/live-value changes rather than byte-identical frames.
Mixed/transient or obscured frames stay Pending as diagnostics; clean reobservation does not establish a cause or fix.
Fixed sleep alone is insufficient; input/charging procedures stay with android-devices/android-emulators.

For AMBIENT acceptance, prove the actual renderer drawMode and intended visible variant.
Dozing or `isAmbient=true` alone does not distinguish MUTE from AMBIENT; preserve MUTE as
a separate valid case. Do not infer absolute part alpha from Doze screenshot RGB. Use the
owning emulator/device workflow for normal-mode observations without data reset and for
restoring temporary DND state; keep operational commands outside this reference.

Before OS-state readback/restoration assertions or compound identity guards, retain bounded expected/actual values and sample identity/hash with target, phase and read time; include the owner-proven setting namespace, requested/stored values, key presence and effective Configuration as relevant; a stored key alone does not prove application. Map the failure trace to the exact executed invocation and body, resolving any traceback line number to its actual guard, before classifying stage or cause; a nearby or remembered guard is not that mapping, and a compound failure alone does not identify which subcondition failed. For a generic send, delivery or other composite-completion failure, resolve the executed predicate and phase and keep each component's measured result or Unknown separate before attributing failure to a sender, receiver or cause. An ambiguous trace does not establish an earlier parser failure. A write receipt is not settled-state proof; a failed guard holds dependent product cases Pending. Later readback is a separate sample and cannot reconstruct unrecorded failure-point values or their cause. After restoring preferences/summary bytes, request the owning normal refresh/reload and
verify the rendered result plus derived caches that can retain data independently. Do
not end restoration at a successful file copy. Preserve existing data and incident proof;
device-preserving operations belong to android-devices/android-emulators, not this skill.

## Case and evidence continuity

Before queuing success-dependent reads/copies/navigation or `view_image`, including inside the same `functions.exec`, branch on the producing leaf's actual successful terminal result (including nested `exec_command.exit_code` and termination signal/status when exposed); `text(await ...)` or other result logging, and outer `functions.exec` completion, are not that branch. Awaited `exec_command` resolution returns a result object; require its actual terminal `exit_code` to be 0 before dependent work. For an asynchronous producer, default to a separate `functions.exec` call for dependent work after observing the producer’s terminal result, including a `write_stdin` result; batch success-dependent calls only behind an explicit terminal-success branch. Before a guard can abort the producing leaf, retain bounded actual guard inputs/diagnostics; later acquisition is a separate sample, not failure-point reconstruction. RUNNING holds dependencies. A success-dependent view also requires fresh membership and case/identity binding to that producer attempt's completed outputs; an existing file alone may be old. After failure, inspect only validated attributable failed/partial diagnostics, never assumed expected success outputs.
While RUNNING, hold dependencies; independent read-only work may continue. Await that same operation's terminal result. After failure, safe attributable failed/partial artifacts may be inspected as diagnostics.
Before transferring expected native files, retain producer diagnostics and confirm the actual file exists and is nonempty; command exit 0, including `uiautomator dump`, is not artifact proof. For native PNG acquisition, retain the actual byte count and signature-match result before the PNG guard can abort, including when bytes exist only in memory; keep any failure classification bounded and sanitized instead of emitting raw private bytes. For a capture requiring an awake display, qualify current display/wake state through the owning device procedure; invalid PNG bytes alone establish no screen-power cause. Before dependent parsing, viewing/indexing or UI action, validate transferred PNG signature/decoding, JSON parsing/expected case content or XML parsing/expected hierarchy; `adb exec-out ... run-as ... cat` can exit 0 with missing-file diagnostics instead. Report missing output as missing; preserve error bytes under a diagnostic text extension and allow necessary safe cleanup.
Diagnostic inspection needs no capture success and does not establish acceptance. Acceptance requires success plus the current candidate/file, capture time/hash and actual content; a path, acknowledgement or old file is insufficient.

Before a new case or reused operational receipt template writes evidence, resolve every effective output path, including embedded paths, and verify it belongs to the fresh owning case directory; require distinct unused destinations and fail before overwriting preexisting case evidence. Earlier phases may already occupy that directory; preserve their receipts, and distinguish read-only Source/reference inputs from outputs. Verify actual target identities separately from receipt destinations; broad string replacement is not path/ownership proof. Keep matched expected/observed states with original native frames/hashes, active instance/binding evidence and capture times.
Separate emulator, physical-device, review-art, fixture and public-image claims. Anonymous display measurements suffice;
retain no credentials, raw provider payloads or unlock/authentication material.

Derive a capture group's window from minimum/maximum measured per-image timestamps, not filenames, array order or one first frame.
Retain the actual timestamp source and timezone; distinguish capture-time observations from file-mtime/export-time evidence.
For indexed or discovered capture views/exports, build the dispatch list only from actual completed manifest/index members or the returned discovered path set and verify each requested file's existence and applicable case/identity binding before queuing; failed/missing expected captures stay Unknown, and intended filenames, planned maxima or printed counts do not add members. Keep diagnostics separate. Reconcile actual output names, counts and identities
with that cohort before publication. A wildcard match or valid image alone does not prove membership; resolve unexpected outputs.

After rebuilding or redeploying, requalify a fresh full web document/loader against the intended served build before metadata or behavior acceptance. Requalify any long-lived preview server against the rebuilt artifact and deployment configuration; retained prior imports may require restarting that owned server before browser acceptance. Fragment/client navigation or a ready URL does not prove consumption of the new artifact; later reads cannot reconstruct an unretained original loader/event or establish its cause.

After navigation, first use a cheap readiness read to qualify the current document/context, expected route and settled body before evaluating styles, fonts or geometry. Evaluate transition-dependent postconditions at their required settled phase and re-read after waiting; a wait does not refresh an earlier sampled object. If evaluation throws, retain bounded actual exception diagnostics and target/phase before aborting; generic errors and later reads do not establish the original cause.

Before each web capture, measure the current browser session's actual viewport and match it to the intended capture target; after reconnect/emulation reset when applicable, reapply required emulation and remeasure through the same live CDP connection/browser session used for case input/capture, without relying on a closed connection's override. A mismatch is diagnostic, never evidence for the intended viewport. Scroll each intended current-theme image into view and boundedly confirm viewport intersection, complete=true and positive naturalWidth/naturalHeight before decoding or capturing.
Do not await hidden/offscreen lazy variants or infer breakage from their unrequested/incomplete state; decode only the individually observed loaded image, then inspect its capture at the measured viewport before acceptance.

Before projecting or asserting native viewport or PNG dimensions, qualify the actual supported current display or window representation, its effective size and the applicability of override and rotation fields for the same target and capture mode; retain that authoritative producer and actual PNG dimensions. For ordinary full-display capture, sufficient qualified native display evidence needs no additional optional window-subsection parser gate; an empty or failed projection leaves only its own geometry observation Unknown and does not establish display absence; independent qualified geometry remains usable, and later reads remain separate samples. Natural size alone does not establish the current overridden, rotated or windowed viewport; unqualified expected dimensions hold dependent actions.
After native-window or emulation geometry changes, inspect a fresh before frame and requalify the current target in that session; retain its actual pre-input rectangle and expected/actual guard facts before assertion or input, without reconstructing a held guard's observation or cause from later reads.

For web heading or legacy-alias acceptance, follow the [user-docs permalink preflight](../../user-docs/references/public-writing.md#public-audience-and-owners) before freezing edit scope or accepting rendered targets.

Before declaring required public screenshot replacements or approving a capture list, follow
the [user-docs freshness scope](../../user-docs/references/screenshots.md#files-frames-and-freshness).
Viewing a PNG establishes its visible content; establish its current use before freezing
replacement scope or marking capture preparation ZERO. Unresolved use classification stays Pending.

Record healthy demonstrations separately without erasing the incident; verify shared public capture state through user-docs.
A valid fixture cannot compensate for an unproved live binding or establish that a reported incident was fixed.
