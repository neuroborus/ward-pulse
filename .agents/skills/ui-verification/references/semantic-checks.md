# Semantic and visual checks

Use before visual acceptance. Start from the owner's actual wording and original native frame. State the requested mismatch before selecting a fix or changing data. A full-ring seam and a cyan pool drawn
on another provider's band are different defects; solving one does not close the other. Resolve ambiguity from the available evidence before guessing.

Before approving geometry or implementation requirements, check each target attribute's type/range in the owning schema and primary documentation for the intended format/version. Confirm representable
sizes and origins, including integer centre/size parity where required; correct floating arithmetic alone is insufficient. Apply integer constraints only to the attributes that require them; legitimate floating properties and transforms remain allowed.
For WFF, inspect the actual emitted XML tree against the primary content model for that version, including child cardinality. [Condition](https://developer.android.com/reference/wear-os/wff/common/condition)
permits one element tree per `Compare`/`Default`. A passing official validator or template containment check does not establish that structural contract.

## Map meaning before judging appearance

Build a compact expected/observed mapping for every selected metric or pair, accounting for missing items and unexpected rendered extras. Use the actual snapshot/summary and owning surface contract. Include:

- provider family and logical metric ID, selected window/pool and its paired mate;
- family/half color, expected band/position and which side of a shared band it owns;
- reported value, remaining/used interpretation, status and optional purchased credits.

Resolve visible band order through `RingSurfaceOrder` and actual effective main/extra bindings before
family, color or geometry claims; payload/picker order alone is not outer-to-inner order. Map absent paint too.
After count, selection or reorder changes, verify BOTH halves of EVERY selected pair against the current native frame: family, band/position, radius AND width must match the current owning geometry.
A retained half can keep an earlier count's footprint while its mate moves. A surviving sliver of the expected color, plausible ring count or updated percentage does not establish correct pair geometry.
When thin adjacent bands are ambiguous, measure radii/widths and overlap at the actual native viewport scale, map both halves to their families, and report unresolved geometry as a finding before PASS; exact-color counts alone do not prove geometry.
A Cursor secondary half sharing Codex's band while its mate occupies another is wrong even if counts/shapes look plausible. Use the existing locked design/ordering rules; do not invent a new visual convention.

When a pair is removed, reordered or absent, verify that the previously occupied split surface no longer
draws stale data. Trace both configured split routes, not only the currently visible first pair. Static
arithmetic or a correct TITLE branch is producer/resource evidence, not proof of the value delivered to the live bound renderer.

## Inspect actual original frames

View the original device/emulator frame, not only a scaled documentation export, preview board, test
status or screenshot filename. Identify the actual visible app/page/renderer and compare it with the
evidence's artifact identities. Review art can be correct while the installed active face is older or uses retained bindings.

For an owner-requested preview approval, deliver the exact artifact through an owner-visible channel.
An internal view, emitted image, file path or successful viewer launch alone does not prove visibility.
If the owner cannot see it or asks to open it, use an existing authorized viewer/channel and verify the
intended artifact/window or obtain owner acknowledgement before claiming it shown or requesting approval.
This delivery check applies to preview handoff; mock approval remains distinct from native acceptance.

Judge the whole affected surface after the final change: every metric/half, legends, units, clipping,
default cells, status controls and navigation context relevant to the case. Do not infer that uninspected
neighboring elements are correct because one detail passed. Verify real circle/screen boundaries before measuring or cropping.

Classify the complete original's intended visible mode and settled state before using glyph/ROI measurements.
Renderer metadata alone does not validate a mixed wake/handoff frame or one covered by an overlay.

Before a causal claim or system correction, identify the emitting component and actual metric owner (watch, peer or other source); compare a current authoritative observation for that owner.
A visible label/content description proves displayed UI state, not the underlying metric or cause. Retain conflicting timed/identified samples separately and leave unresolved ownership/cause Unknown.
Do not choose power changes, clearing or restarting from the label alone. This does not block independently authorized read-only observation or capability work.
Existing mutation, custody and recovery safeguards remain in force.

Before concluding an artifact is absent or unchanged, inspect bounds proven to cover its full geometry, including displaced caps and paired halves.
Before interpreting counts, bind RGB/ARGB encoding, channel order and alpha convention to the actual owning candidate constant; record exact probe colors, ROI and scale.
The independent reviewer must challenge apparent zeros for wrong encoding/color and ROI adequacy. Zero changed pixels in a narrow ROI proves only that ROI; compare the whole footprint before dismissing a native artifact.
Exact-color counts alone do not prove alpha or geometry. The whole-footprint comparison alone does not establish a renderer cause.

For upper face cells, inspect EVERY rim's full contour and its clearance to neighboring cells, time and
bands in the original native frame, with a magnified view when needed. Compare original outward lighting
and each explicitly added treatment with the current owning design. A request to change one side's fade
does not remove the other side's fade; **no added bottom fade** does not mean **no fade anywhere**.
Record unchanged lighting regions and compare matched before/after native upper/arc-facing regions
separately from the new lower treatment on EVERY cell before PASS. Direction on the new side alone is
insufficient. Populated default cells do not prove clean rendering: look for unexpected pale flecks,
stray strokes and broken contours around them. Keep border fades, unexpected artifacts and usage-progress
arcs as separate checks. If a missed artifact is reported after acceptance, preserve the incident frame,
reopen the review and keep the public capture candidate Pending until actual repair and matched native verification.

Immediately before input, revalidate the current page AND a unique enabled visible intended node or its own
enabled clickable ancestor from a fresh hierarchy and original frame; its label/context and current bounds
must support safe action. Inspect both `text` and `content-desc`: either may identify the target while the other is empty.
Do not reuse a picker/modal observation across model/tool round trips; prefer one prepared existing observation/action batch.
Stop absence-driven scrolling once the target is visible; reveal a clipped target only for usable bounds.
One empty label field or a selector ignoring the populated field does not prove absence. Ambiguous matches,
disabled controls, stale nodes or the wrong window stay unresolved; reobserve or disambiguate within the existing bounded procedure.
If an ephemeral page is dismissed, stop and record it; reopen by the existing ordinary route and observe fresh,
without blindly replaying input. After action, verify the actual settled destination and relevant resource/instance
or effective binding. A found node or successful command/input does not prove it reached the intended page.
For composite fields, use [Form visibility](form-visibility.md) to check the editor, error and actions independently;
a wrapper's hit-test result alone does not establish them.

Choose gesture extent and commit requirements for the actual component being navigated, using its real unclipped viewport
and intended gesture region. Neighboring legend bounds, clipped accessibility children and another component's remembered
successful gesture are not substitutes. After settlement, verify the actual destination or reached limit before accepting success
or treating an uncommitted gesture as a navigation defect. Distinguish actual system font/DPI state from an injected test density or animation scale.

## Match the case after changes

Preserve the failing input/state and compare like-for-like before/after frames after the candidate is installed and active; record intentional state changes separately without substituting percentages, pair membership or a fresh fixture.
Bind EACH frame used for geometry/persistence/change/recovery claims to its own original hash, case joins and measurement. Never borrow the first frame's ROI result or infer persistence from unchanged Source; report each observed temporal result separately, keeping cause distinct and unproved unless established.
An observed success covers that target/state, not every device or retained-install path.

After temporary preferences or a fixture are restored, verify actual derived surfaces again using the
[state/artifact reference](state-and-artifacts.md). Restored file bytes alone do not establish restored complications, widget caches or the active scene.

Healthy public examples follow user-docs. Preserve the incident privately when preparing a clean demonstration; do not replace
the incident with healthy data and call the bug fixed. Public coherence is required independently of the incident's diagnostic value.
