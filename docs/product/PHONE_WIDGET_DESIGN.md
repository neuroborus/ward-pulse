## Goal and size/composition rules

A glanceable **remaining** summary fills the actual launcher widget allocation in both dimensions, using WardPulse's existing day/night surfaces and its own bundled typography. Widget selections stay independent of Watchface slots. The maximum remains **six** selected metrics; each shown row is complete and each hidden trailing row is omitted. No filler rows or unowned aggregate metric is added.

The accepted nominal examples are 360×344 with six rows, 266×184 with three rows and labels, and 150×184 with three percentage-only rows. The first references a measured 360.38×344dp allocation; the other examples are illustrative. These host-art units are a proportional baseline, not universal launcher thresholds, SP values or proof of native raster fit. Actual host options, pixels and density determine measured fit. Maintain horizontal and vertical resize handles without a tight maximum height; do not overwrite launcher-owned sizes or tell the user to shrink the span to a small hugging card.

The full card retains the existing light `#F2F4F1` / dark `#101412` surface, rounded corners, hairline, family accent bars and quiet mono mark. Keep both Cursor pool colors distinct. A fresh card has no header. Center a compact complete-row block with useful spacing inside the allocation; normal breathing room with fewer rows is acceptable. Do not replace unused space with stretched text or giant column/row gaps.

| Element | Approved nominal style |
| --- | --- |
| Remaining percentage | Noto Sans **30 Bold 700**; complete numeric token |
| Eligible purchased balance | **26 Bold 700**, end aligned |
| Family / full pool name | **18 Bold 700** / **16 Regular 400**, two lines |
| Optional reset | **11 Regular 400**, muted, lower line in every row |
| Row / row gap / content margin | **44 / 8 / 16** |
| Main column allowances | accent/value **12**, percentage **77**, label **127**, details **100**, two gaps **6** |

Measure actual native ink and full strings before layout. `Cursor` / `Models` follows the same two-line family/pool composition as `Cursor` / `Other Models`, `Codex` / `Weekly plan` and `Claude` / `5-hour session`; preserve actual catalog meaning, not arbitrary text splitting. The quiet mark is an overlay with its own top/frame clearance (nominal 36×15 visible ink, top 2, end margin 16), separate from content margins. It must not collide with content or state messages.

When width is insufficient, omit a reset that would crowd a valid balance, then the entire right-detail column, then the label column. Keep complete percentages and full accessible identities. When height is insufficient, omit complete trailing rows; do not reduce the six-selection limit. Never force fit by ellipsis, silent label abbreviations, clipped glyphs, stretched bitmaps or shrinking the approved primary hierarchy.

The declared baseline covers approved English labels, numeric tokens and reset formatting plus other glyphs actually verified in the bundled fonts. Arbitrary localized/unbounded text is not guaranteed to fit. Apply whole-column fallback rather than an unknown system-font substitution. If no complete row fits, render `Resize widget`; if no eligible resolved metrics exist, render `No metrics`. Use bundled 12 Regular for these minimum text fallbacks; on an exceptionally small host that cannot fit the complete message, retain the accessible state without cropped visible text.

## Metric rules and optional reset

**Metric-color revision 2026-11-01.** Exact metric
`allowance.claude.claude-seven-day-fable` takes `#FF8A00`; ordinary Claude remains
`#E8915A`. Similar labels/IDs, legacy windows, Anthropic budgets and provider/status
chrome do not inherit this exception. Expanded independent rows, six selections,
purchased-credit eligibility, real optional resets and known-zero/unknown behavior
are unchanged. This Source palette decision does not close pending native/public acceptance.

1. **One slot = one percent metric of one connection** — one connection's local budget for a
   period, a provider plan window, or a purchased meter (Extra usage, on-demand, credits %) when
   the provider reports a %. There is no summed Today / Week / Month slot: see
   `WATCH_RING_DESIGN.md` layer rule 1 for why a percentage across connections has no owner.
2. **Claude and Codex plan windows stay expanded** on the phone widget: Claude `5h`,
   `Weekly`, Opus/Sonnet weekly when present; Codex main and Spark primary/secondary
   windows when reported, including `Spark 5h` / `Spark Weekly`. Existing per-window
   selections survive unchanged. Watchface/Glance collapse Claude to one ring and Codex
   independently to one main-limit ring and one Spark ring before pairing.
3. **Cursor Models and Other Models** are separate selectable rows whenever the usage-summary
   reports both pool percents.
4. **Remaining language** — display `(100 - usedPercent)` for percent metrics; family colors match
   the product palette in `WATCH_RING_DESIGN.md`, where a Cursor plan's two pools carry their own
   colors since 2026-08-13. A budget row takes the family color of its connection; the neutral
   grey is a fallback for an unresolved family, not a product color.
5. **Purchased credits** — on **plan** rows, when that provider family reports finite purchased
   remaining credits, show columns: `N%` · label · compact balance (for example `59.5K`).
   Accessible descriptions retain the units. Same per-provider rule as Wear Glance / face
   strips — not a footer sum, not `creditsGlance`, never LLM `TOK`. Skip on purchased-meter rows (Extra
   usage / on-demand are the credit pool), budgets, and missing/unlimited balances.
6. **Omit** unavailable metrics (no percent). Exhausted plan/purchased meters (`usedPercent >= 100`)
   stay on the phone widget as **`0%`** so sibling pools remain visible. Watch/WFF likewise
   retain known selected exhausted metrics under their 2026-10-13 revision. The Widget tab
   states unavailability rather than hiding it: a metric with no
   percentage lists as unselectable under its own reason — *This allowance has no percentage to
   show*, seen on `Purchased credits` 2026-10-11 — so the rule is legible to whoever is choosing.
7. **No credentials**, account ids, or raw provider payloads on the widget or in widget logs.

Default selection prefers plan windows, then purchased meters, then configured local budgets. Selection is shared by placed widgets; resize never deselects hidden rows. Display order stays used percentage descending, then stable metric ID. Show only `N%` and compact balances visually; accessible descriptions retain remaining/credit meaning. Do not synthesize live rows or replace current payload values with the approved board's historical photo/Opus/illustrative examples.

A reset is optional and belongs to the selected allowance's actual `AllowanceState.resetsAt` instant. Use stable identity through the phone-private payload and clear absent/removed fields; old caches without reset fields remain valid. Budget/missing reset boundaries are not invented or inferred from a label, duration or sibling window.

Display the actual instant in the device-local zone, consistent with the phone's `formatLocal`; keep the current English widget copy with **`Reset DD MMM HH:mm`**, for example `Reset 04 Nov 12:00`. The day is zero-padded. All present resets use the same lower line, nominal top 29 within a 44-unit row; a purchased balance stays above with the approved 3-unit gap. Missing resets leave no fake text. The sample UTC reference and shared illustrative dates are not native policy or provider facts. An absolute reset is not a live availability guarantee; no minute ticker or fabricated rolling reset is added. Normal payload/lifecycle updates reformat the current instant, including timezone changes.

## Own-font rendering, states and accessibility

Use explicit app-bundled Noto Sans Regular 400 and Bold 700 for every visible widget string, including stale/empty/no-fit messages. Preserve the approved font binaries and required OFL notices/third-party attribution. Font family, weight and density-based size do not depend on system typeface, fontScale or force-bold; this does not promise identical raster pixels or all-Unicode coverage on every device.

The existing AppWidgetProvider/RemoteViews uses four fixed decorative bitmap layers (primary text, secondary text, stale text and accents) plus the mono mark. `PhoneWidgetRenderer` measures native ink and advance with the bundled faces; `PhoneWidgetLayout` owns the complete-row/column plan used for both fitting and painting. Density-based pixels are displayed without bitmap-density scaling. Native resource tints preserve the day/night palette.

The root background fills the allocation. Host-provided size options select at most two Android 12 size variants; older or unusual hosts retain a conservative fallback. Each bitmap dimension is bounded to 4096 pixels, and the complete variant set is bounded to the lower of 8 MiB and the platform screen-based bitmap allowance. Full updates replace the prior image set. No host-owned size option is written and no unbounded renderer/cache is introduced.

The current verified font repertoire used for visible text is printable ASCII plus middle dot, en dash, em dash and right apostrophe, with a bounded string length. Unsupported text follows whole-column omission and retains its full accessible identity. No system face is substituted. The complete `No metrics` / `Resize widget` message takes priority over decoration on unusually short hosts; an exceptionally tiny host retains the accessible state without clipped visible text.

For stale retained data, reserve the measured own-font 11 Bold `STALE` padded line plus the existing density-scaled 2-unit gap; the identical inset governs both row fitting and drawing. Fresh state removes it. Keep all visible glyphs and the watermark clear in day/night, empty and no-fit states.

Preserve one root accessibility summary and the existing Dashboard tap/readiness behavior. Every visible logical row retains its full metric identity even when its label is hidden, plus remaining meaning; announce credit/reset details only when displayed. Hidden rows are omitted and decorative content is not announced again. This preserves the existing aggregate contract without requiring a new row-focus framework.

### Size caps (locked)

| Size | Slots shown | Notes |
|------|-------------|--------|
| Short | **1–2** | fewer metrics in Widget tab (~1–2 cells) |
| Mid | **3–5** | typical place size (`targetCellHeight≈3`) |
| Tall | **6** | prefs cap (`phoneWidgetSlotCount`) |

Prefs select up to **six** metrics; the olive card shows as many **complete** resolved
rows as fit the host cell, and as many **complete** columns as fit the width
(`wrap_content` hug). Trailing rows / right-hand columns that would clip are omitted —
never half-cut text. Horizontal drop order: **credits → label → `%`**. Vertical /
horizontal resize changes the launcher span; drag handles to the card to reclaim empty
cells. Newly placed widgets default to ~3 cells tall; **remove and re-add** if an old
tall span stays stale. Unused slots stay omitted, not filled.

Default (unset) selection prefers **plan windows** first (Claude + Cursor + Codex), then
purchased meters, then local budgets — so 5h / weekly / Cursor Models / Other Models are not
crowded out by Extra usage. A budget row only becomes selectable once its connection has a
limit for that period, so an unconfigured install defaults to plan windows.

### Composition (locked)

```text
┌─ olive card hugs complete rows + columns ──────┐
│  ▌ 22%          Claude       80           ⌇wm  │  ← tightest remaining first
│  ▌            Weekly plan                      │
│  ▌ 46%          Claude      320                │
│  ▌           5-hour session                    │
│  ▌ 71%       Cursor Models  2.1K               │
└────────────────────────────────────────────────┘
┌─ mid (credits dropped) ────────────────────────┐
│  ▌ 22%         Weekly                     ⌇wm  │
│  ▌ 46%           5h                            │
└────────────────────────────────────────────────┘
┌─ narrow (% only) ──┐
│  ▌ 22%        ⌇wm  │
│  ▌ 46%             │
└────────────────────┘
     (transparent cell beyond the card if the span is larger)
```

- Rows, not concentric arcs.
- Family accent bar (▌) on each metric row.
- **Columns** — remaining `%` · centered label · compact purchased balance (end-aligned).
  Only the numeric columns omit visible `left` / `credits`; the Widget tab stays descriptive.
  One widget accessibility description names each visible metric and its remaining percentage,
  plus purchased credits only when that column and balance are present; child cells do not
  speak again. Hidden rows contribute nothing. Width hide order:
  credits first, then label; missing credits still reserve the credits column when that
  column is shown (label stays centered).
- **Label is two lines** (revised **2026-08-02**) — family on top, pool below. The provider
  must be readable at the baseline text scale; larger scales can ellipsize the fixed-width
  columns, as measured at 1.5 in the 2026-10-13 acceptance above. Nothing else names it:
  colour alone cannot tell one `Weekly plan` from another. The column keeps its fixed
  width, so the cost is height, not width: rows are `ROW_CONTENT_DP` 31 instead of 17 and
  the card hugs taller. Every row reserves both lines (`android:lines="2"`), so a label
  that already carries its family — `Cursor Models` — leaves the second line empty rather
  than making rows uneven.
- **Day / night** — olive phone chrome (`#F2F4F1` / `#101412` via `values` /
  `values-night`), not provider fills. Soft 20dp card + hairline outline; runtime card
  **hugs** complete content so unused cell area is wallpaper. Widget-picker preview uses a
  dedicated sample layout (`ward_pulse_app_widget_preview`) that hugs the sample rows
  (no empty olive band under them) and follows the same day/night colors when the system
  theme is dark.
- **Resize** — `horizontal|vertical` with **no** tight `maxResizeHeight` (a span taller than
  the max makes Pixel drop vertical handles). Height / width decide how many **complete**
  rows / columns fit. Newly placed widgets use `targetCellHeight≈3`; **remove and re-add**
  after metric-count changes if the launcher keeps a stale tall span.
- **Watermark** — same faded mono as the watch face, ~36dp overlay top-end (does not
  reserve a header band). Fresh widgets have no dedicated header.
- Empty: short “No metrics” line (no filler rows).
- Too short for a complete resolved metric: “Resize widget”, with no clipped metric rows.
- Stale: compact uppercase “STALE” top-start when the last dashboard is stale. Reserve its
  measured padded line plus 2dp above content and subtract that same space when fitting rows;
  remove the inset when fresh.
- Tap opens the phone app (Dashboard).
